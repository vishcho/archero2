# Repository instructions for AI agents

This repository is a static tournament archive. These instructions apply to Codex, Claude Code,
and other automated contributors working anywhere in the repository.

## Source of truth

- `data/` is the website's only structured source of truth.
- `docs/` contains human-readable rules, reports, and analysis. Do not copy facts from generated
  Markdown back into JSON unless a workflow explicitly describes a legacy migration.
- `docs/README.md` is generated by `tools/build-docs-index.mjs`; never edit it by hand.
- `screenshots/` contains local source evidence and is gitignored. Do not commit screenshots.
- `tmp/` contains unverified extraction results and is gitignored. Never make the website or
  committed documents depend on it.

## Data invariants

- Files are UTF-8. Preserve Chinese, Korean, emoji, and other original player-name characters.
- A Star Cup id is its knockout start date and must equal `knockout_period[0]`; it is not the
  season's actual first day.
- Tournament series have deliberately different schemas. Dispatch through `data/cups.json`; do not
  force `season` and `roster` records into one shape.
- `groups[].players` order is draw position, not display order. Never sort it alphabetically or by
  rank. It is **not** a reliable source for who plays whom: `groups[].matches` (`round` + `slot`) is
  the only authority for bracket structure, and `players` only supplies display attributes.
- `roster[].enchants` array indexes are equipment slots. Preserve interior `null` placeholders.
- Use `player_id` as player identity. Names and aliases are display data and may be duplicated or
  change over time. Never merge players solely because their names match.
- Do not guess unreadable OCR values. Keep the value absent/unknown as allowed by its schema and
  record uncertainty in the relevant source notes.

## Normal workflow

1. Read the relevant file in `notes/workflows/` before importing or changing tournament data.
2. Make the smallest source-data or source-document change needed.
3. Run `npm run check` from the repository root.
4. If document membership or titles changed, run `npm run docs:build`, commit the regenerated
   `docs/README.md`, then run `npm run check` again.

`npm run check` is the canonical completion gate. Do not report a data change complete when it
fails. Existing warnings about uncollected historical finals, duplicate display names, or documented
missing screenshot batches are not failures; do not hide or auto-fix them without new evidence.

JSON shape is governed by `schemas/`; cross-file and tournament rules remain domain validation.
Tools that change `data/` must support `--dry-run`, validate the complete candidate before writing,
and use the atomic JSON writer in `tools/lib/`.

## Change boundaries

- Prefer editing existing plain HTML, JavaScript, JSON, and Markdown. Do not introduce a framework,
  build system, dependency, or schema migration unless the task requires it.
- Import and backfill tools that modify formal data should be previewed with `--dry-run` when the
  tool supports it.
- Preserve unrelated user changes in a dirty worktree.
- Never modify evidence, player identity, historical results, or uncertainty markers merely to make
  validation output quieter.

## URL 慣例

- 站內連結不帶 `.html`：寫 `href="bracket?id=…"`，首頁寫 `href="/"`。實體檔名仍是
  `bracket.html`，只有 URL 去掉後綴。
- GitHub Pages 原生支援這種 extensionless 解析；`tools/dev-server.mjs` 也比照實作，讓本機與線上
  行為一致。舊的 `.html` 網址仍可存取，外部既有連結不會失效。
- `href` 之外提到 `.html` 的地方（工具讀檔路徑、程式註解）指的是實體檔案，不要一併改掉。
- `tools/dev-server.mjs` 只服務會部署的內容：`screenshots/`、`tmp/`、`notes/`、`tools/`、`test/`、
  `schemas/`、`node_modules/` 與所有 dotfile 一律 404。新增網站用目錄時要確認它不在 `BLOCKED`，
  新增工作用目錄時要記得加進去。`assets/`（css 的 @font-face）與 `docs/` 是線上內容，不可封鎖。

## Useful commands

```bash
npm run check
npm run validate
npm run docs:build
node tools/check-screenshots.mjs
```
