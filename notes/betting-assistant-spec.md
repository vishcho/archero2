# 明星盃下注建議工具規格

更新日期：2026-08-14

## 產品定位

本站的主要目的是「下注助手」，賽事資料庫是支援下注分析與賽後驗證的次要功能。

使用者的首要任務是在當屆明星盃的下注日，快速完成 8 組、每組 7 場，共 56 個一次性下注選項。下注機會只在隔週五當天的 24 小時內開放，所有輪次必須在開賽前一次選完。

本站只提供建議，不代表賽果保證，也不因資料不完整而阻止使用者查看建議。

## 用戶與使用情境

主要使用者同時可能是：

- 賽前需要快速完成 56 場下注的玩家。
- 賽後整理賽果與驗證建議的資料維護者。
- 長期研究玩家表現的分析者。
- 將網站分享給其他玩家的發佈者。

每一組都會下注，不需要「找到自己」、收藏玩家或勾選「已下注」。

## 產品資訊架構

### 首頁

首頁只顯示最新一屆明星盃，不直接攤開所有歷史屆次。主要內容包含：

- 當屆名稱、期間與下注狀態。
- 「下注建議」主要入口。
- 戰力覆蓋率：有戰力資料人數 / 64。
- 資格賽覆蓋率：有排名及時間人數 / 64。
- 歷史覆蓋率：有可採計上屆紀錄人數 / 64。
- 強制選擇場次數 / 56。
- 本屆目前命中數 / 已結算數。
- 上一個完整結算屆次的命中數 / 已結算數。
- 正式歷史累計命中數 / 已結算數。
- 資料更新時間、已知缺漏與「僅供下注建議」提示。

次要入口必須明確分開：

- 歷屆下注成效。
- 完整賽事資料。
- 超級明星盃。

### 下注建議頁

下注建議頁以對陣圖為主要作業介面，協助使用者快速對照遊戲內的對陣位置。必須提供：

- 8 組快速切換。
- 每組完整對陣圖與金色建議路徑。
- 遊戲操作順序：`A → B → C → D → R2 上 → R2 下 → 組冠軍`。
- 每組 7 個明確選項。
- 每場建議的信心等級、主要判斷依據與資料缺漏。
- R2 與組冠軍選項依賴的上游預測晉級者。
- 單組 7 場與全部 56 場的純文字複製功能。

本頁不提供已下注勾選或下注進度追蹤。

### 賽事結束後

賽事結束後，原「下注建議」內容改為同時呈現：

- 當時的正式下注建議。
- 實際比賽結果。
- 逐場命中、未命中或尚未結算狀態。
- 每組與本屆命中率。
- 對陣圖上的預測路徑與實際路徑比較。

介面不再以仍可下注的語氣呈現歷史賽事。

### 歷屆下注成效

歷屆成效頁以預測表現為主，包含：

- 最近一屆命中數 / 已結算數。
- 正式歷史累計命中數 / 已結算數。
- 各屆、各組與逐場結果。
- 預測來源：保存快照或賽前文件還原。

### 完整賽事資料

保留資格賽排名、淘汰賽完整資料、總決賽與玩家歷史資料，但定位為支援下注分析的次要功能。

### 錯誤狀態

下列情況不得只留下空白頁或未處理的 Promise rejection：

- 缺少或無效的屆次 `id`。
- 不存在的賽事類型。
- JSON 載入失敗。
- 資料結構無法呈現。

錯誤畫面必須說明問題，並提供返回首頁、查看最新一屆與查看歷史資料的選項。

## 下注判斷規則

### 判斷順位

每場以下列順位選擇建議對象：

1. 上屆淘汰賽進度。
2. 上屆同進度時的通關時間。
3. 本屆戰力。
4. 資格賽排名。
5. 資格賽時間。
6. 固定選擇對陣資料中的 `p1`。

高順位指標能分出勝負時就定案，低順位指標不得翻案，只能影響信心與風險提示。即使本屆戰力差距達 50%，只要上屆表現可明確比較，仍選擇上屆表現較好者。

### 上屆表現

- 先比較淘汰賽進度：組冠軍／組決賽／R2／R1。
- 進度相同時，比較上屆通關時間，時間較短者優先。
- `未入選` 低於任何有參賽紀錄者。
- 同名但玩家身分不確定的歷史紀錄完全不採計。

### 資料不足與強制選擇

每組七場都必須產生選項。資料不足時仍依上述順位選擇，戰力是沒有可用歷史表現後的主要強制選擇依據。所有指標均無法分辨時，固定選擇 `p1`。

強制選擇必須：

- 明確標示資料缺漏。
- 說明最終使用的指標。
- 照常計入正式命中率。
- 在首頁顯示強制選擇數量。

R2 與組冠軍建議必須建立在預測晉級路徑上。若上游場次資料不足，仍可產生後續選項，但必須顯示其依賴關係與風險。

### 信心與強制選擇

- 以上屆表現定案，且至少一個低順位指標同向時，初始信心為 `high`；沒有低順位支持時為 `medium`。
- 沒有可比較的上屆表現而改用戰力、資格賽排名或資格賽時間時，標記 `forced: true`，初始信心最高為 `medium`。
- 所有指標均無法分辨而選擇 `p1` 時，信心為 `low`。
- 任一低順位指標反向時只降低一級信心，不改變選擇。
- R2 或組冠軍依賴的上游含強制選擇時，再降低一級信心。
- `star-cup-v1` 起每場保存發布當下的上屆表現、戰力與資格賽 evidence；日後修正客觀資料時不回寫 evidence。由舊 Guide 還原的 `legacy-guide-v1` 仍以原文件理由為準。

## 正式預測快照

### 生命週期

1. 蒐集並驗證資格賽、對陣、戰力與歷史資料。
2. 由維護者手動確認資料已可發布。
3. 生成當屆唯一一份正式預測快照。
4. 下注窗口內只讀取該快照，不因程式或原始資料變更而重算。
5. 下注窗口結束後封存快照。
6. 賽果收錄後，以封存快照逐場比對與計算命中率。

候選與發布命令：

```bash
npm run predictions:preview -- <season-id> --matchup <r1-matchup.json>
npm run predictions:publish -- <season-id> --matchup <r1-matchup.json>
```

`matchup` 只允許 8 組各自的 A、B、C、D 客觀對陣，不包含 winner。正式發布需要明確的
`--publish --confirm`，會拒絕覆寫既有快照並同步更新預測屆次索引。

每屆不維護一般性多版本。當屆正式快照一旦發布，下注選擇不得因日後演算法更新而改寫。

### 資料修正

正式快照發布後仍允許修正 OCR、玩家身分或對陣等客觀事實，但：

- 修正賽事事實時不得事後改寫正式下注選擇。
- 原預測與修正後事實必須可區分。
- 修正導致原預測對陣無法直接對應時，該場保留原選擇並標記「來源資料更正」。
- 不得為改善命中率而事後重算。

### 預測來源

正式統計只採計：

- `snapshot`：下注前由維護者確認後保存的正式快照。
- `document_reconstruction`：由當時的賽前下注 Guide 還原，且可追溯至賽前文件的預測。

`retrospective`（賽後重算）只供研究，不得宣稱為當時建議，也不進入正式 KPI。

## 命中率

核心 KPI 為全部場次命中率：

```text
命中率 = 命中場次數 / 已收錄實際賽果的場次數
```

規則：

- 未收錄賽果的場次不進入分母。
- 強制選擇照常計入命中率。
- 命中數、已結算數與各種命中率由正式快照與賽果即時計算，不寫死在 JSON。
- 本屆尚未完整結算時，首頁可同時顯示本屆目前成績、上一完整屆成績與正式歷史累計成績。

## 資料契約

### 賽事事實

現有 `data/star-cup/{id}.json` 與 `schemas/season.schema.json` 繼續保存賽事事實，包含資格賽、分組、戰力、歷史摘要與賽後結果。本功能不需要破壞或遷移現有 season 格式。

### 預測快照

新增獨立資料目錄：

```text
data/
└── predictions/
    └── star-cup/
        ├── seasons.json
        └── {season_id}.json
```

預測快照不混入 season JSON，因為客觀賽事事實可依新證據修正，但已發布的下注選擇必須保持不變。

單屆預測檔必須至少保存：

- `season_id`。
- 發布狀態與 `published_at`。
- 預測來源。
- `ruleset`（判斷規則版本）。
- 發布當下的三種資料覆蓋率。
- 強制選擇場次數。
- 8 組、每組 7 場，共 56 筆選擇。
- 每場的輪次、slot、`p1`、`p2`、建議對象、信心、依據、缺漏、是否強制選擇與上游依賴。
- 如有事實修正，保存不改寫原選擇的更正註記。

玩家身分應優先使用 `player_id`，並同時保存發布當下的顯示名稱。

### 驗證要求

實作時應新增 `schemas/prediction.schema.json` 與跨檔案 domain validator，至少檢查：

- `season_id` 對應已存在的明星盃屆次。
- 正好 8 組 × 7 場。
- 場次必須包含 `A/B/C/D/upper/lower/final`。
- 建議對象必須是該場 `p1` 或 `p2`。
- R1 預測晉級者正確進入 R2，R2 預測晉級者正確進入組冠軍場。
- 正式預測不得引用發布後才出現的賽果。
- 一屆只有一份正式快照。
- 命中率計算只使用已結算場次。

## 歷史資料遷移

既有屆次依來源分類：

- 有賽前下注 Guide：可還原為 `document_reconstruction`，但必須保留來源文件路徑與還原說明。
- 沒有當時建議：不得宣稱為當時預測。如以新規則重算，只能標記為 `retrospective`。
- 從下一屆開始：預設使用手動確認後的 `snapshot`。

## 驗收條件

- 首頁首要內容是最新一屆下注建議，歷史屆次不全部攤開。
- 每屆正式快照正好有 56 個建議選項。
- 使用者可依照遊戲操作順序與對陣圖快速完成每組 7 場下注。
- 所有建議皆可說明判斷依據、缺漏與上游依賴。
- 資料不足時仍產生建議，但清楚標記強制選擇。
- 正式快照發布後，修正賽事事實不會改寫原下注選擇。
- 賽事結束後可逐場比較當時建議與實際結果。
- 命中率分母只包含已結算場次，強制選擇照常計入。
- 只有 `snapshot` 與 `document_reconstruction` 進入正式 KPI。
- 無效網址或資料載入失敗會顯示可理解的錯誤與返回選項。
- `npm run check` 包含預測契約、晉級路徑與命中率測試並全數通過。

## 不在本階段範圍

- 超級明星盃的手機版比較介面與資訊架構，待另案討論。
- 實際代為使用者下注。
- 已下注勾選、投注進度追蹤或個人收藏。
- 投注報酬率或每組冠軍命中率作為主要 KPI。
- 導入後端服務、帳號系統或資料庫。
