# Archero 2「塔塔的寶藏」UI/UX 設計評論與改善建議

## 評估範圍

本報告整合以下兩個層級的評論：

1. 社群分享預覽圖：暗色卡片、角色圖示、「明星盒助手」主標與「精靈季」說明。
2. 完整網站：首頁、明星盃下注建議、賽事資料、歷史成效、單屆賽事詳情及響應式規則。

網站部分依據本機專案中的 HTML、CSS、JavaScript 產生內容與資產進行評估。由於目前環境無法直接開啟線上站點，真實瀏覽器的字型渲染、網路載入時間與實機互動不在本次範圍內。

## 整體結論

設計已成功建立「暗黑 × 金色 × 寶藏 × 賽事資料工具」的品牌方向。首頁具備清楚的產品定位、成熟的色彩控制及合理的內容層級；社群預覽圖也能延續相同氛圍。

目前主要問題不是美術方向，而是：

- 跨頁設計系統尚未完全統一。
- 細字、低對比與手機版極小文字影響可讀性。
- 高密度賽事資料仍以桌面版思維呈現。
- 部分導覽、互動暗示與資料指標不夠直觀。
- 社群預覽圖的對齊、邊框結構及空間配置仍可精煉。

綜合評價：約 **7.5／10**。視覺方向已成立，下一階段應由「做得好看」推進到「跨頁一致、容易閱讀、容易操作」。

## 共通設計優點

### 1. 品牌視覺具有辨識度

- 深黑與炭灰建立專業、沉穩的資料工具基調。
- 低飽和金色呼應寶藏、稀有度及競賽獎勵。
- 角色與遊戲圖示帶來親和力及識別性，但沒有壓過資訊。
- 淡格線背景增加科技與遊戲感，使用相對克制。

### 2. 產品定位清楚

首頁主標「賽事預測、歷史數據與實用攻略」能快速說明網站價值。本期焦點、主要功能、下注成效與最近資料的順序，也符合使用者由當期任務進一步探索歷史內容的路徑。

### 3. 首頁資訊層級成熟

- 主標題先交代網站價值。
- 本期焦點提供最重要的當期操作。
- 實心金色與深色按鈕能區分主要及次要 CTA。
- 功能、成效和最新資料分區明確，方便快速掃讀。

### 4. 已具備響應式基礎

首頁雙欄區塊、功能卡及成效區會在窄螢幕轉為單欄；導覽列也允許水平捲動，顯示網站已考慮不同裝置，而非只設計桌面版。

### 5. 資料狀態表達相對完整

載入中、尚未發布、資料缺口、強制選擇、推薦正確及錯誤等狀態都有對應文案或視覺樣式，適合資料型產品。

## 全站主要問題與建議

### P0：跨頁設計系統不一致

`season.html` 沒有沿用 `css/site.css` 的暗金色變數、共用頂部導覽與頁尾，而是使用 Tailwind CDN 及另一套 slate／亮黃色介面。

影響包括：

- 從首頁進入賽事詳情時，像被導向另一個網站。
- 品牌色、圓角、間距、標題及返回方式全部改變。
- 維護時需要同時處理兩套 UI 規則。
- Tailwind CDN 載入失敗時，頁面視覺可能明顯退化。

建議將 `season.html` 納入共用 shell、topbar、footer 與 CSS token；保留既有資料邏輯，不必為了統一外觀全面重寫。

### P0：手機版賽程圖文字過小

在 520px 以下，賽程圖中的玩家名稱縮至 10px，輔助資料縮至 9px。雖然版面能塞進螢幕，內容卻不一定能有效閱讀，對中文字及較長玩家名稱尤其不利。

建議：

- 不要直接縮小完整桌面賽程圖。
- 手機版改成逐輪、逐組或直向卡片視圖。
- 提供「賽程圖／列表」切換，並以列表作為小螢幕預設。
- 正文與關鍵資料盡量維持至少 12–14px。

### P1：導覽資訊架構不一致

- 首頁導覽最後一項是「遊戲攻略」，其他頁面則是「賽事資料」。
- `history.html` 將「明星盃」標示為 active，且連結回 `bracket.html`，無法準確表達所在位置。
- `season.html` 只有「返回列表」，缺少完整主導覽。

建議固定一級導覽：

1. 首頁
2. 明星盃
3. 超級明星盃
4. 賽事資料
5. 遊戲攻略（未完成前可先不列入主導覽）

歷史成效與單屆資料可透過麵包屑或次級導覽表達位置。

### P1：部分卡片的互動暗示不一致

「明星盃」與「超級明星盃」卡片可以點擊，但「遊戲攻略」使用近似造型，實際上只是不可點擊的 `article`，容易讓使用者以為功能失效。

建議：

- 未完成項目移除箭頭、hover 效果及連結式視覺。
- 或提供可點擊的預告頁，清楚說明目前狀態。

### P1：資料指標缺少語意解釋

「戰力 64/64」、「資格賽 64/64」、「歷史 64/64」對熟悉資料模型的人很清楚，但一般玩家未必知道它代表「已收集／總人數」。

可改為：

- 戰力資料：64／64 人
- 資格賽資料：64／64 人
- 歷史資料：64／64 人

「強制選擇」等專有概念也應提供簡短 tooltip 或說明。

### P1：鍵盤焦點與可存取性不足

CSS 有 hover 及 active 狀態，但缺少完整的 `:focus-visible` 規則。鍵盤使用者可能無法判斷焦點位於哪個導覽、按鈕或卡片。

建議：

- 為連結、按鈕、頁籤及可點擊卡片加入一致的焦點外框。
- 在頁首加入「跳至主要內容」連結。
- 確保頁籤具有正確的 ARIA role、選取狀態與鍵盤操作。
- 不要只用顏色表達推薦、晉級、正確與錯誤狀態。

### P2：中英文標籤略顯混雜

`Archero 2 community tools`、`Tools`、`Performance`、`Latest` 與繁體中文標題混用。目前這些英文較像模板式 eyebrow，而非必要資訊。

建議統一為中文，只保留真正需要的英文品牌名稱。例如：

- Community Tools → 社群資料工具
- Tools → 主要功能
- Performance → 預測成效
- Latest → 最近更新

### P2：次要文字及頁尾對比偏弱

大量輔助資訊使用 muted 灰色，頁尾則使用較暗且僅 11px 的文字。在低亮度螢幕或戶外環境中可能不易辨識。

建議使用 WCAG 對比度工具實測，提高頁尾與輔助文字亮度或字級；細小文字不應只靠些微色差區分。

### P2：高密度表格仍偏向桌面操作

賽事詳情表格會同時包含場次、排名、玩家、戰力、資格賽時間與上屆資料。雖然資訊完整，手機使用者卻需要反覆左右捲動，容易失去欄列定位。

建議：

- 手機版將每位選手改成兩欄資訊卡。
- 或固定第一欄與表頭，降低捲動時的定位負擔。
- 預設只顯示核心欄位，將上屆細節放進展開區。

### P2：互動回饋尚未形成完整規格

部分卡片 hover 會改框線或上移 1px，但缺少統一 transition；按鈕也缺少一致的 hover、pressed、loading 等狀態。

建議建立共用互動規格：

- 120–180ms 的顏色、位移與陰影 transition。
- 完整定義 hover、active、focus-visible、disabled 及 loading。
- 尊重 `prefers-reduced-motion`。

## 首頁專項評論

首頁是目前完成度最高的頁面，主標、本期焦點與功能入口層級合理，暗金色也使用得相對克制。

可再改善之處：

- 首屏同時出現大標、本期焦點及四項指標，資訊量稍高，可降低次要數據的視覺重量。
- 「8 組共 56 場完整預測路徑」是重要賣點，可以比日期與賽季描述更突出。
- 「本屆資料」語意略廣，可改成「查看本屆名單」或「查看賽事資料」。
- 最近資料中的狀態可改成 badge，提升掃讀效率。

## 明星盃／下注建議頁專項評論

遊戲化賽程圖比純表格更符合題材，金色與橘色路徑也能強化推薦方向，是網站最有特色的視覺元件之一。

主要風險：

- 暗金網站風格與賽程圖的紫紅、亮黃、橘色略有分裂。
- 線路、節點、選手卡及推薦狀態同時競爭注意力。
- 手機版直接縮小整張圖，犧牲文字可讀性。
- 若顏色代表晉級、推薦或落敗，應提供固定圖例。

## 賽事資料／歷史頁專項評論

列表與表格結構務實，適合查找資料，但可增加：

- 依盃賽類型、日期及狀態篩選。
- 搜尋選手名稱。
- 顯示目前套用條件與結果數量。
- 空狀態提供清除篩選或返回最新賽事的操作。

## 社群預覽圖專項評論

### 優點

- 深色與低飽和金色能準確傳達寶藏及稀有感。
- 「明星盒助手」作為主標，視覺焦點明確。
- 左上角色圖示增加品牌識別及親和力。
- 淡格線背景增加遊戲感，但不會過度搶戲。
- 留白讓畫面安靜、高級，不顯擁擠。

### 問題與改善方式

#### 1. 字體過細

白色及金色文字採用極細字重，在一般螢幕、手機縮圖或投影環境中容易模糊，長句的閱讀負擔尤其明顯。

- 主標改用 Medium 或 Semibold。
- 副標與描述至少使用 Regular。
- 提高白色及金色文字對比。
- 針對社群平台實際縮圖尺寸檢查可讀性。

#### 2. 垂直空間過於鬆散

左上品牌資訊與中央內容之間存在大面積空白，主內容又集中在中下方，使留白比較像空洞，而非刻意安排。

- 將主標與描述整組上移約 30–50px。
- 或加入明確 CTA／功能提示平衡下方空間。
- 使用固定間距系統，例如 8px grid。

#### 3. 邊框結構不自然

金色上框醒目，但左右線條在上半部中斷，容易讓人誤以為元件遭裁切或尚未完成；角色圖示也沒有真正形成頁籤或卡片接點。

- 降低金色框線亮度，避免搶走標題焦點。
- 將邊框完整包覆卡片。
- 若要表現頁籤，需讓角色圖示與框線形成明確結構關係。

#### 4. 副標資訊層級不清楚

「精靈季」與功能描述主要依靠顏色區隔，但字級與字重接近，不易判斷前者是分類、版本或活動名稱。

- 將「精靈季」設計成小型標籤或膠囊元件。
- 同時使用字級、字重及間距區分資訊角色，不要只依賴顏色。

#### 5. 對齊邏輯分裂

頂部內容採左對齊，中央內容採置中，兩區沒有共同基準線，看起來像兩種版型被組合在一起。

- 選定單一方向：全部置中，或全部對齊共同左側格線。
- 品牌列、主標與描述應建立可辨識的對齊關係。

#### 6. 功能描述語句可更自然

原文：

> 獲得精靈和飛劍流派技能

建議改為：

- 取得精靈與飛劍流派技能
- 解鎖精靈及飛劍流派技能

若畫面具有操作目的，可加入「查看技能」或「開啟明星盒」等明確 CTA。

## 統一設計系統建議

### 色彩

- 保留 near-black、charcoal、muted gold 與 soft off-white 核心配色。
- 金色主要用於 CTA、active、重要數值及少量品牌裝飾。
- 為成功、錯誤、推薦、落敗定義固定語意色，並搭配文字或圖示。

### 字體

- Display／H1：Semibold。
- H2／卡片標題：Medium 或 Semibold。
- 正文：Regular。
- 輔助文字：Regular，不使用極細字重。
- 手機版關鍵文字不低於 12px，正文以 14–16px 為宜。

### 間距與版面

- 採用一致的 8px spacing scale。
- 共用最大內容寬度、頁面左右 padding、卡片 padding 與 section gap。
- 每頁沿用相同的 header、main 與 footer shell。

### 元件

優先統一以下元件：

- 主／次按鈕
- 頁籤
- 狀態 badge
- 可點擊功能卡
- 資料卡與指標卡
- 表格與手機版資料卡
- 空狀態、載入狀態及錯誤狀態
- tooltip 與圖例

## 實作優先順序

### 第一階段：一致性與基本可用性

1. 將 `season.html` 收斂至共用暗金設計系統。
2. 統一所有頁面的 header、導覽 active 狀態與 footer。
3. 補上 `:focus-visible`、skip link 及基本 ARIA tab 行為。
4. 提高極細、極小及低對比文字的可讀性。

### 第二階段：改善手機核心任務

1. 為賽程圖提供手機列表模式。
2. 重整手機版高密度表格。
3. 將最小關鍵文字維持在可讀尺寸。
4. 為顏色狀態補上圖例或文字標記。

### 第三階段：提升理解與產品完成感

1. 解釋資料覆蓋率與「強制選擇」等指標。
2. 統一中英文標籤、卡片 affordance 及互動狀態。
3. 為歷史資料加入搜尋、篩選與空狀態。
4. 重新整理社群預覽圖的字重、對齊、標籤及邊框。

## 最值得優先完成的修改

若目前只能處理一項工作，建議先將 `season.html` 改用共用 shell 與 `site.css`。這能一次改善品牌一致性、導覽、維護成本與跨頁體驗，也是後續統一表格及手機元件的基礎。

若接著處理第二項，應重新設計手機版賽程內容，而不是繼續縮小桌面賽程圖。
